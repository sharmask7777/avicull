# avicull Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `avicull`, a local-first, deterministic command-line system in Rust for macOS (Apple Silicon) that projects immutable trip-based bird photo archives into a species-organized directory tree using POSIX hard links, multi-stage YOLO11 bird detection, BioCLIP visual classification, SINR spatio-temporal prior weighting, burst consensus smoothing, and transactional SQLite rollback manifests.

**Architecture:** A dual-component design consisting of a minimal Python ONNX exporter script (managed via `uv`) to produce static `.onnx` models and precomputed taxonomy embeddings, and a high-performance modular Rust CLI/library (`types`, `scanner`, `geo`, `detector`, `classifier`, `burst`, `organizer`, `db`, `cli`) with trait-abstracted ML inference engines for zero-dependency testability.

**Tech Stack:** Rust (2021 edition), `ort` (CoreML / ONNX Runtime), `candle-core` / tensor math, `nom-exif` & `kamadak-exif`, `image` (Lanczos3), `rusqlite` (bundled), `clap`, `walkdir`, `blake3`, Python 3.12 + `uv` (`torch`, `onnx`, `safetensors`).

**Spec:** `docs/superpowers/specs/2026-10-24-avicull-spec.md`

## Global Constraints
- Strict source immutability: The input directory (`--input`) must never have any file moved, renamed, modified, or unlinked.
- Separate output tree via hard links (`std::fs::hard_link`): Files in `--output` share the exact APFS inode (`st_ino`) with zero extra data payload storage.
- Upfront volume & disjointness validation: `fs::metadata(&input)?.dev() == fs::metadata(&output)?.dev()` verified before any processing, and paths must not be nested ancestors of each other.
- Filename format: `<OriginalStem>_<Confidence:0.2>.<OriginalExt>`, preserving original casing and handling compound sidecar extensions (`DSC_4011.JPG.xmp` -> `DSC_4011_0.96.JPG.xmp`).
- Deterministic collisions: Same inode = no-op; different inode = prefix `<TripSlug>__`.
- All domain types serializable (`serde::Serialize`, `serde::Deserialize`) and decoupled from filesystem side effects.
- Must pass `cargo fmt --check`, `cargo clippy -- -D warnings`, and `cargo test`.

## Review Focus
1. Cross-volume or nested path inputs: Verify upfront detection before any read or inference occurs.
2. Compound extensions and case preservation: Verify `.ARW.xmp`, `.JPG.XMP`, and mixed-case stems/extensions are grouped into the same bundle and formatted correctly.
3. Embedded JPEG extraction fallback: When RAW files (e.g. `.ARW`, `.CR3`) lack a companion JPEG, correctly locate and parse embedded JPEG preview markers `0xFFD8`..`0xFFD9`.
4. High-visual-similarity out-of-range vagrant species: Ensure geo-prior floor $\epsilon = 0.01$ and power $\alpha$ properly down-rank lookalikes without causing numerical underflow or division by zero.
5. Inode-aware idempotency: Running `organize` or `relink` twice on the exact same directory must be a clean no-op, neither duplicating links nor raising error `EEXIST`.
