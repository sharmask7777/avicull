Architectural Design & Data Flow

Extending human overrides from avian-only to multi-category preserves the core zero-cost, high-performance architecture of avicull while removing taxonomic hardcoding.

1. Strongly-Typed Domain Model Refactor (src/types.rs)

Replaces stringly-typed reverse-engineering with a first-class Classification domain struct on BundleDecision:

pub struct Classification {
    pub category: AssetCategory,
    pub entity_slug: Option, // Some("Snow_Leopard") or None for top-level kingdom/genre
}

pub struct BundleDecision {
    pub bundle_id: String,
    pub classification: Classification,
    pub routing_tier: RoutingTier,
    pub is_user_override: bool,
    ...
}

2. Catalog Data Serialization (src/catalog/mod.rs)

Zero-bloat JSON: retains species_list: Vec<String> for birds (100% backward-compatible) and adds compact multi_taxa: Vec<CuratedTaxonEntry> (~40 KB) for non-avian categories.

2. CLI & Manifest Dispatch (src/organizer/correct.rs)

The CLI command avicull correct --category <CAT> --species <SLUG> --file <TARGET>:

  • Normalizes --category into the strong Rust enum AssetCategory.
  • Disables avian typo suggestions when category is non-avian, preventing false bird prompt warnings on mammals or landscapes.
  • Allows freeform custom species/genre names so users are never blocked.
  • Transactionally updates BundleDecision in .avicull/manifest.sqlite with is_user_override = 1.

Three-Mode Invariant Enforcement

As confirmed during brainstorming, subfolder routing and disk modifications vary strictly by mode to honor source immutability:

Organization Mode Source Disk Modification Filesystem Action SQLite Manifest Action
--mode in-place
(Default Preferred)		 Strictly Read-Only (0 bytes) No moving, copying, or renaming. Files remain untouched. Records category, assigned_species, and is_user_override = 1 in manifest.sqlite.
--mode in-place-rename
(Cosmetic Opt-In)		 Atomic In-Place Rename Renames image & sidecars with ..._<Category>_<Species>... tokens. Records new stems in manifest and transactionally logs rollback entries in in_place_rename table.
--mode hierarchy
(Zero-Byte Projection)		 Zero Bytes (Hard Links) Creates birds_hierarchy/<Category>/<Species>/ (or <Category>/ for root genres) via hard links. Updates birds_hierarchy links and updates decision in manifest.sqlite.

Verification Strategy & Invariants

  • Unit Tests: Validate category slug normalization, non-avian typo matching, and freeform slug sanitation in tests/test_suite/test_correct.rs.
  • Filesystem Integration Tests: Verify across all three modes that:
    • in-place keeps source archive completely bit-for-bit unchanged while updating SQLite.
    • in-place-rename atomically renames files with Mammalia_Snow_Leopard tokens and verifies rollback via avicull clean.
    • hierarchy creates correct APFS hard links in birds_hierarchy/Mammalia/Snow_Leopard/ sharing inode numbers.
  • Playwright E2E Tests: Automated browser test verifying:
    • Clicking "Correct Species" opens the multi-category modal.
    • Clicking "Mammalia" switches autocomplete suggestions to mammals.
    • Typing "Snow Leopard" and submitting queues the command into apply_corrections.sh.
    • Multi-select batch correction queues multiple files lockstep.
