# Durable and Portable SQLite Manifest with User Classification Overrides

**Issue:** https://github.com/sharmask7777/avicull/issues/8
**Status:** Approved

## 1. Intent & Context
Currently, `avicull` stores run metadata and bundle decisions in `.avicull/manifest.sqlite`. However:
1. Bundle identity in SQLite and during scanning links directly to absolute filesystem paths and machine-local POSIX inodes (`st_ino`). When a trip folder is copied, rsynced, backed up to an external volume, or opened on another user's laptop, inodes and absolute paths differ, preventing a fresh `avicull` run from deserializing and caching previous decisions.
2. When a user manually corrects a classification—either by dragging/moving files on disk, running a CLI command, or downloading corrections from the HTML catalog—`avicull` must reliably record this correction into the SQLite database as an immutable manual override (`final_confidence: 1.0`, `RoutingTier::ConfirmedSpecies`).
3. Future runs must honor these durable overrides and not re-execute expensive AI detection/classification inferences on them.

## 2. Goals & Non-Goals

### Goals
- **Portable Bundle Identity**: Enable cross-machine portability so another person/instance can open the same directory, read `.avicull/manifest.sqlite`, and deserialize all previous bundle decisions without missing cache hits.
- **Durable Disk Move Reconciliation**: Detect manual moves/renames in the directory (e.g., user moved photo from `_Needs_Review/Mallard` to `Northern_Pintail`), promote the change to a manual user correction in SQLite, and preserve it across subsequent runs.
- **CLI Correction Command**: Add `avicull correct` subcommand to allow programmatic and interactive reclassification of bundles/photos with immediate manifest updates and hardlink/inplace file updates.
- **HTML Catalog Script Synergy**: Ensure `apply_corrections.sh` generated by the catalog invokes `avicull correct` (or updates SQLite directly) so manual web review choices persist into SQLite.
- **Preserve Source Immutability**: The source folder (`--input`) remains strictly read-only in hierarchy mode; all file link updates occur in the output tree (`birds_hierarchy/`).

### Non-Goals
- Modifying remote network APIs or cloud sync daemons.
- Altering the core BioCLIP / ONNX inference architectures.

## 3. Architecture & Data Structures

### A. Portable Bundle Key
A bundle's persistent portable identity across filesystems is determined by:
- Relative primary path within the scanned root (e.g. `Leh_2024/DSC_0001.CR2` or `DSC_0001.CR2`).
- Original stem + trip folder name (e.g. `(trip_folder_name, original_stem)`).
- Secondary fallback: Content hash / BLAKE3 of the primary file header or relative path.

### B. SQLite Schema Migration / Extensions
In `.avicull/manifest.sqlite`:
- In `bundles` table:
  - Add `is_user_override INTEGER NOT NULL DEFAULT 0`
  - Add `relative_path TEXT`
- Add index on `(trip_folder, original_stem)` for fast portable lookups.
- Maintain backward compatibility for existing manifests by altering tables safely if columns are missing.

### C. Manual Move Detection & Reconciliation
During `organize`:
1. Scan current output directory (or input directory in in-place mode) to inspect where bundles currently reside.
2. If a bundle that was recorded in SQLite is now located in a folder corresponding to a different species slug (and not in its previous destination), register a manual move override.
3. Update `bundles` table with `assigned_species_slug = <new_slug>`, `routing_tier = 'ConfirmedSpecies'`, `final_confidence = 1.0`, `is_user_override = 1`.

### D. Subcommand: `avicull correct`
CLI usage:
```bash
avicull correct --input <PATH> [--output <PATH>] --file <FILENAME_OR_STEM> --species <SPECIES_SLUG_OR_NAME>
```
Actions:
1. Resolves bundle in the manifest by relative path, filename, or stem.
2. Updates SQLite record: `assigned_species_slug`, `routing_tier = ConfirmedSpecies`, `final_confidence = 1.0`, `is_user_override = 1`.
3. If hierarchy mode: moves or relinks existing hardlink to the new species directory (`birds_hierarchy/<species_slug>/...`).
4. If in-place mode: renames file and sidecars to reflect the new species.
5. Regenerates `catalog.html` with updated counts and badges.
