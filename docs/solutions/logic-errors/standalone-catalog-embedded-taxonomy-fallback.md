# Eliminating Catalog False Non-Subject Routing via Embedded Clements Taxonomy Fallback

## Problem
In `avicull`, the standalone interactive HTML catalog ([`src/catalog/template.rs`](file:///Users/shaleensharma/workplace/gemini_ws/avian_rearranger/src/catalog/template.rs)) allows users to submit classification overrides client-side. The client-side function `resolveTargetCategory(species, fallbackCategory)` determines whether a user-entered species name belongs to `AssetCategory::Bird` or should be relegated to `AssetCategory::NoSubjectDetected` (`"No_Subject_Detected"`). To prevent non-avian subjects (e.g., statues, landscapes, plants) from being forced into bird directories, the catalog enforces a strict negative invariant: **never assume unknown entities are birds**.

To identify avian species client-side, the catalog checks if the species exists in `CATALOG_DATA.species_list`. However, during catalog generation in clean test or headless CI environments where local model caches (`~/.cache/avicull/models/taxonomy.json`) do not exist, `load_species_taxonomy_list()` in [`src/catalog/mod.rs`](file:///Users/shaleensharma/workplace/gemini_ws/avian_rearranger/src/catalog/mod.rs) fell back to a hardcoded 37-species list (`fallback_curated_species()`). As a result, valid global avian species like `Brahminy Kite` or `Osprey` were absent from `CATALOG_DATA.species_list`, causing the catalog to misclassify user corrections as `No_Subject_Detected`.

## Symptoms
- In integration tests evaluating catalog JavaScript execution (e.g., [`tests/test_suite/test_catalog.rs`](file:///Users/shaleensharma/workplace/gemini_ws/avian_rearranger/tests/test_suite/test_catalog.rs#L1794)), correcting a photo to "Brahminy Kite" generated `No_Subject_Detected` instead of `Bird/Brahminy_Kite`, causing CI test failures on PR #51.
- In headless or offline environments where external model weights and taxonomy files had not been downloaded, the catalog correction modal failed to route legitimate bird names to avian directories.
- Shell scripts generated by the catalog modal emitted:
  ```bash
  avicull correct --category "No_Subject_Detected" --species "Brahminy_Kite" ...
  ```
  instead of routing to `AssetCategory::Bird`.

## What Didn't Work
- **Relying solely on external model taxonomy files on disk**: In standard user desktop runs, `load_species_taxonomy_list()` reads `~/.cache/avicull/models/taxonomy.json`. However, CI runners and containerized environments intentionally run in isolation without external cache downloads.
- **Using a small curated list (`fallback_curated_species`)**: Maintaining a hand-picked 37-species list proved brittle. It caused false-negative routing for every valid bird species outside the small curated subset, breaking tests and user workflows across diverse geographies.
- **Loosening the client-side unknown-species gate**: Allowing unknown entities to default to `AssetCategory::Bird` was explicitly rejected, as it violates the core invariant established to prevent plants ("Sacred lotus", "Banyan tree") and scenery from being filed as birds.

## Solution
1. **Expose Canonical eBird World Taxonomy**:
   In [`src/types.rs`](file:///Users/shaleensharma/workplace/gemini_ws/avian_rearranger/src/types.rs#L56-L77), exposed `canonical_bird_common_names()` backed by the embedded compile-time Clements/eBird world taxonomy (`data/taxonomy.json`, containing 11,243 species):

   ```rust
   static CANONICAL_BIRD_COMMON_NAMES: LazyLock<Vec<String>> = LazyLock::new(|| {
       let mut names = Vec::new();
       if let Ok(records) = serde_json::from_str::<Vec<serde_json::Value>>(TAXONOMY_JSON) {
           for r in records {
               let cat = r.get("category").and_then(|v| v.as_str()).unwrap_or("Bird");
               if cat == "Bird" {
                   if let Some(cname) = r.get("common_name").and_then(|v| v.as_str()) {
                       names.push(cname.to_string());
                   }
               }
           }
       }
       names.sort();
       names.dedup();
       names
   });

   #[must_use]
   pub fn canonical_bird_common_names() -> &'static [String] {
       &CANONICAL_BIRD_COMMON_NAMES
   }
   ```

2. **Authoritative Embedded Fallback in Catalog Generation**:
   In [`src/catalog/mod.rs`](file:///Users/shaleensharma/workplace/gemini_ws/avian_rearranger/src/catalog/mod.rs#L903-L908), updated `load_species_taxonomy_list()` so that when disk caches are unavailable, it defaults to the full embedded canonical taxonomy:

   ```rust
   // Default to authoritative embedded canonical eBird taxonomy
   let canonical = crate::types::canonical_bird_common_names();
   if !canonical.is_empty() {
       return canonical.to_vec();
   }

   fallback_curated_species()
   ```

3. **Preserved Client-Side Invariant**:
   In [`src/catalog/template.rs`](file:///Users/shaleensharma/workplace/gemini_ws/avian_rearranger/src/catalog/template.rs#L1997-L2010), `resolveTargetCategory()` continues to strictly verify `isKnownBird` against `CATALOG_DATA.species_list`. Because `CATALOG_DATA.species_list` now contains all 11,243 canonical bird species even in isolated environments, valid birds are correctly routed to `AssetCategory::Bird` while non-avian subjects are safely routed to `No_Subject_Detected`.

## Why This Works
The root cause was an environmental dependency gap: the client-side catalog UI relied on a complete bird taxonomy to distinguish birds from non-birds, but the server-side generator only loaded the complete taxonomy if a disk cache existed.

By backing the catalog fallback with the binary-embedded Clements taxonomy (`data/taxonomy.json`), the catalog generator is completely hermetic and zero-dependency. Offline catalogs, CI test runners, and air-gapped environments receive the exact same 11,243-species taxonomic validation as fully provisioned production environments, satisfying both invariants:
1. Valid birds across all continents are reliably identified as `AssetCategory::Bird`.
2. Non-bird entities (plants, statues, scenery) never default to birds.

## Prevention
- **Avoid Partial Fallbacks for Authoritative Sets**: When domain logic depends on membership testing against a closed universe (such as Clements world avifauna), fallback data must never be a truncated sample if the full dataset can be embedded at zero runtime cost.
- **Hermetic CI Validation**: Always ensure end-to-end browser and CLI tests run against the same embedded data structures that ship with the binary.
- **Automated Catalog Logic Verification**: Validate client-side JavaScript execution both via Node subprocesses in Rust integration tests ([`tests/test_suite/test_catalog.rs`](file:///Users/shaleensharma/workplace/gemini_ws/avian_rearranger/tests/test_suite/test_catalog.rs)) on CI and interactively via local Playwright specs ([`tests/e2e/`](file:///Users/shaleensharma/workplace/gemini_ws/avian_rearranger/tests/e2e/)).
