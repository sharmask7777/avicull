# Duplicate Stem Query Disambiguation and Unambiguous Relative Paths in Catalog

## Problem
In multi-folder photo archives (e.g. multiple trips or nested directories such as `Dubare - 2/.../dubare_19.jpg` and `Kashmir and Dubare -1/.../dubare_19.jpg`), camera conventions frequently produce identical bare file stems across different subdirectories:
1. When users attempted to correct species or update locations using commands generated from `catalog.html`, commands previously emitted bare stems (`--file "dubare_19"`), triggering runtime ambiguity errors (`Error: Multiple photo bundles matched query 'dubare_19'`).
2. In `catalog.html`, batch command queues (`addToBatch`) keyed entries by `b.stem === it.original_stem`, causing edits for photos with duplicate stems in different directories to overwrite each other.
3. In `src/db.rs:find_bundle_by_query` (invoked by `avicull location --file`), multi-bundle matches did not trigger an ambiguity error, instead silently returning the first matching bundle.
4. When querying for files in subdirectories renamed in-place (`<date>_<loc>_<stem>`), an asymmetry in stem matching (`rel_s.ends_with(&format!("_{}", bundle.original_stem))`) omitted the search query, causing any query in that directory to match unrelated files.

## Symptoms
- Executing generated correction commands produces:
  ```
  == avicull correct ==
  Error: Multiple photo bundles matched query 'dubare_19':
    - Dubare - 2 and nagarhole 2024 /Processed - compressed/dubare_19.jpg
    - Kashmir and Dubare -1  2024/Processed/Dubare compressed/dubare_19.jpg
  Specify an unambiguous relative path using --file (e.g. --file "<trip>/<file>").
  ```
- Setting locations via `avicull location --file <target>` silently modifies the wrong bundle when the file stem appears in multiple subdirectories.
- Querying a nonexistent file in an in-place renamed folder reclassifies a real photo instead of returning a not-found error.

## What Didn't Work
- **Using `current_path_rel` in hierarchy mode**: In hierarchy mode, `current_path_rel` reflects the projected taxonomic folder (e.g. `_No_Subject_Detected/...`), which does not correspond to the source relative path needed for CLI commands.
- **Bare stem stripping without root indicators**: Stripping `./` unconditionally prevented disambiguating a root photo from a subfolder photo of the same name.

## Solution
1. **Unambiguous `relative_path` in Catalog Payload**:
   In `src/catalog/mod.rs`, `CatalogPayloadItem` now serializes `relative_path: Option<String>` derived directly from `item.subdirectory` and `primary_filename` (e.g. `"Dubare - 2 .../dubare_19.jpg"`).
2. **Catalog Command Generation & Batch Keying**:
   In `src/catalog/template.rs`:
   - Single-item and batch move command generators emit `targetItem.relative_path || targetItem.original_stem`.
   - Batch items in `addToBatch` are keyed by `itemKey = it.relative_path || it.id || it.original_stem`, ensuring distinct items in separate folders never collide.
   - Location commands in `applySubdirLocation`, `reclassifyScopeContext`, and `reclassifyDiffItems` emit `targetFile` with shell escaping.
3. **Ambiguity Enforcement in `find_bundle_by_query`**:
   In `src/db.rs`, `find_bundle_by_query` collects matches per priority tier. If more than one candidate matches a non-exact query, it returns an explicit error listing all matching relative paths and instructions to specify an unambiguous `--file "<path>"`.
4. **Root Disambiguation with `./`**:
   Both `src/organizer/correct.rs` and `src/db.rs` parse `./<file>` and `.\\<file>` without internal path separators as explicit root directory queries (`is_explicit_root`), filtering candidate bundles to those whose relative path parent is empty.
5. **Symmetric Renamed Stem Matching**:
   Corrected the renamed file matching logic in both `correct.rs` and `db.rs` so `target_s` is verified against `rel_s` prefix and suffix:
   ```rust
   if rel_s == target_s
       || target_s == bundle.original_stem
       || (!target_s.is_empty()
           && (rel_s.starts_with(&format!("{target_s}_"))
               || rel_s.ends_with(&format!("_{target_s}"))))
       || (!bundle.original_stem.is_empty()
           && (target_s.starts_with(&format!("{}_", bundle.original_stem))
               || target_s.ends_with(&format!("_{}", bundle.original_stem))))
   ```
