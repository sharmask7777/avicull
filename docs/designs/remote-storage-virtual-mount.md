## Problem Statement

Wildlife photographers accumulate massive archives (often tens of thousands of RAW files totalling terabytes) stored across heterogeneous locations: local APFS SSDs, Network Attached Storage (Synology/TrueNAS over SMB/NFS), and object storage clouds (AWS S3, MinIO, Cloudflare R2, Proton Drive).

Current tools either force duplicate local copies or lock the user into database-centric walled gardens (Immich, PhotoPrism, Lightroom Catalogs). `avicull` needs to classify and structure these archives with zero byte duplication and without eagerly downloading 50–80 MB RAW files across high-latency networks.

## What Makes This Cool

**The Invisible Zero-Copy Teleport:**
Point `avicull` at a 10TB S3 bucket or home TrueNAS SMB share, and within seconds browse a native macOS Finder volume (`/Volumes/Avicull`) structured by Clements/eBird taxonomy (`/Aves/Accipitriformes/Accipitridae/Haliaeetus_leucocephalus/`). 

Every image opens in Finder, Lightroom, or QuickLook instantly—because `avicull` pulls only the embedded preview JPEG or targeted RAW byte ranges on demand, caching hot blocks in a local NVMe LRU cache without duplicating a single byte of storage on the target archive.

## Constraints

1. **Strict Source Immutability**: The remote or cloud source is strictly read-only. Never mutate, rename, or write metadata into the input archive.
2. **Byte-Efficient Remote Range Requests**: Zero full RAW file downloads during scans. Only stream the first ~128 KB for TIFF IFD tags and the exact ~1.5 MB embedded preview slice.
3. **No Driver Dependencies**: Avoid third-party kernel extensions or `macFUSE` requirements. Use native macOS loopback mount interfaces (`mount_webdav http://127.0.0.1:<PORT> /Volumes/Avicull`).
4. **Apple Silicon Acceleration**: Retain existing Metal/CoreML acceleration for bird detection and Bayesian spatial-temporal prior fusion on streamed preview frames.

## Premises

1. **Premise 1 (Byte-Efficient Remote Access)**: When scanning remote SMB/NFS mounts or S3 buckets, `avicull` must never pull entire RAW payloads; it extracts embedded previews via HTTP `Range` requests or partial byte-range seeks.
2. **Premise 2 (Zero-Mutation Virtual View)**: Remote archives without APFS hardlink support are presented through a virtual filesystem projection and SQLite catalog without rewriting remote files.
3. **Premise 3 (Modular Storage Backend)**: Storage backends are decoupled through an extensible Rust trait (`StorageBackend`), allowing unified support for local disks, SMB, and S3.

## Cross-Model Perspective (Independent Review)

- **The Coolest Unconsidered Version**: A dynamic taxonomic WebDAV loopback (`dav-server-rs`) mounted directly into macOS Finder (`/Volumes/Avicull`), projecting the eBird/Clements taxonomic hierarchy as native folders with on-demand byte-range streaming.
- **The Core User Passion**: *"Seamless Hybrid Lens: Auto-index local drives + NAS + Cloud storage (iCloud/S3/Proton) into a unified visual taxonomy with zero duplicate bytes."* — An obsession with zero storage redundancy and transparent multi-tier accessibility.
- **The 50% Off-The-Shelf**: [Apache OpenDAL](https://github.com/apache/opendal) for Rust. It provides a production-grade, async abstraction across S3, SMB, WebDAV, AzBlob, and local FS with connection pooling and range queries.
- **The 50% to Build**:
  1. Partial TIFF/RAW IFD parser extracting embedded preview offsets with 2 minimal byte-range requests.
  2. Taxonomic VFS Projection combining SQLite predictions with `dav-server-rs`.

## Approaches Considered

### Approach A: Smart HTTP/WebDAV Virtual Mount with Apache OpenDAL & Range-Request RAW Previews (Selected)
- **Summary**: Integrate Apache OpenDAL as the unified async storage engine. Build a two-request RAW embedded preview extractor (`Range: bytes=0-131071` then preview byte slice) and expose classified photos as a read-only macOS Finder volume via `dav-server-rs`.
- **Effort**: Medium (M)
- **Risk**: Low
- **Pros**:
  - Zero disk duplication across remote S3, NAS, and cloud backends.
  - Finder and desktop apps (Lightroom, Capture One) can navigate the virtual taxonomic hierarchy out-of-the-box with no special plugins.
  - Native macOS WebDAV client (`mount_webdav`) requires zero third-party drivers or kernel extensions.
- **Cons**: WebDAV has slight protocol latency compared to native APFS hard links, though mitigated by local NVMe preview caching.
- **Reuses**: Existing `classifier.rs`, `detector.rs`, `geo.rs`, and SQLite manifest infrastructure.

### Approach B: Lightweight Embedded Streaming Engine + Standalone Web Catalog (Zero Mount)
- **Summary**: Stream embedded previews from remote buckets via OpenDAL and generate a responsive, self-hosted web catalog serving thumbnails from SQLite.
- **Effort**: Small (S)
- **Risk**: Low
- **Pros**: Simplest implementation, no OS mount management.
- **Cons**: Creative desktop applications cannot directly open RAW files via Finder.

### Approach C: Progressive Local Sync Cache (On-Demand Hydration into Inode Hardlink Tree)
- **Summary**: Progressively download full RAW files on demand into a designated local APFS cache volume and construct traditional APFS hardlink trees.
- **Effort**: Large (L)
- **Risk**: High (Disk exhaustion on large archives; violates zero duplicate bytes invariant).

## Recommended Approach

**Approach A**: Combines Apache OpenDAL for multi-cloud/NAS byte-range extraction with a lightweight local WebDAV virtual mount. Delivers the full promise of zero duplicate bytes while integrating seamlessly into the macOS desktop environment.

## Open Questions

1. **Credential Management**: Should S3/Cloud credentials be read from standard environment variables (`AWS_ACCESS_KEY_ID`), an `avicull.toml` configuration file, or macOS Keychain?
2. **Offline Mode**: How should the virtual mount behave if a remote S3 bucket or NAS disconnects while browsing? (Recommendation: Keep cached preview thumbnails readable, flag full-RAW downloads as offline).

## Success Criteria

1. **Byte Efficiency**: Scanning a remote 100-photo Canon CR2 / Sony ARW folder pulls $< 180 \text{ MB}$ total across the wire instead of $> 5 \text{ GB}$.
2. **Mount Parity**: Running `avicull mount s3://my-wildlife-bucket /Volumes/Avicull` mounts the taxonomic tree in Finder within 2 seconds.
3. **Immutability**: Zero write operations or changes to the remote source bucket.
